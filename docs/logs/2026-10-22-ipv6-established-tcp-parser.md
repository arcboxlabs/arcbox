# Validated IPv6 established TCP input

Use shared IP/TCP views for established-flow lookup, sequence and ACK handling, receive windows, and payload boundaries. A bridge-local parser checks Ethernet/IP family agreement and the bare-packet size limit. SYN rejection shares the same parser and retains its payload-aware reset ACK. IPv6 extension headers no longer interfere with TCP field offsets. Inline hints keep the shared IP and TCP parsing functions visible to hot-path optimization without removing structural checks. Invalid input returns before changing flow state.

The dedicated xuan-work-mbp test Mac passed 146 splicetcp and 60 arcbox-packet library tests with all features and no ignored tests, strict all-target/all-feature Clippy, workspace formatting, and default-feature consumer compilation. Validation used Rust 1.96.0 and a fresh build directory. The new socket-backed regression checks both Ethernet and bare-IP input: every truncation boundary, malformed lengths and extension/header fields, wrong EtherType, Hop-by-Hop options, trailing padding, wrapping ACKs, receive-window updates, and exact uploaded bytes. Existing SYN rejection and IPv4 upload/backpressure regressions also passed.

The [paired benchmark](../benchmarks/network.md#2026-10-22--established-tcp-input-validation) measures parser cost through actual bridge APIs. The user's Surge analysis separates address-family handling from transport dispatch; this batch applies that boundary to established TCP input. IPv6 batch coalescing, handshake parsing, classifier activation, and native lifecycle acceptance remain pending. Original App, NE, VPN, DNS, and interface state remained unchanged.
