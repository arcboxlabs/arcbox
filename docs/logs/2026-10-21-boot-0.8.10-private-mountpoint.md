# 2026-10-21 — Boot assets 0.8.10 restore bind mounts from macOS temporary directories

- Type: change
- Area: boot assets (`assets.lock`), guest VirtioFS shares
- Commits / PRs: [boot-assets #63](https://github.com/arcboxlabs/boot-assets/pull/63), this change
- Related: #249 (the `/private` VirtioFS share), #754 ([`host-gateway` reaches the Mac](2026-10-19-host-gateway-reaches-the-mac.md))

## Problem or trigger

Docker bind mounts from `/tmp`, `/private/tmp`, `/var/folders` and `/private/var/folders` failed on every EROFS boot bundle. The Docker proxy rewrites those sources into `/private` (`app/arcbox-docker/src/host_path.rs`), and the guest mounts the host `private` share there (`mount_virtiofs_optional` in `guest/arcbox-agent/src/init.rs`). The EROFS rootfs had no `/private` directory. `mkdir_p` failed on the read-only root, the mount then failed, and the agent logged it at debug only. Compose builds from the default macOS temporary directory (`$TMPDIR`) hit the same failure.

## What was done

- boot-assets #63 adds `private` to `MOUNT_DIRS` (`src/build/rootfs.rs`), so the rootfs carries the mountpoint.
- [Release run 39490341402](https://github.com/arcboxlabs/boot-assets/actions/runs/39490341402) published [v0.8.10](https://github.com/arcboxlabs/boot-assets/releases/tag/v0.8.10) from `d82611ffbe2651958c797e51e75fc62019cdcd92` with kernel `v0.0.25`, the same kernel as 0.8.9.
- `assets.lock` pins `[boot]` 0.8.10.

Against 0.8.9, the manifest changes only the version, the rootfs digests, and the rebuilt `containerd` and `FEX` artifacts. Kernel digests, `dockerd`, `runc`, `k3s` and `firecracker` are unchanged.

## Evidence

- The manifest from `boot.arcboxcdn.com` hashes to the GitHub release's `manifest.json` digest. The ARM64 kernel and rootfs from the CDN match the manifest.
- `dump.erofs --path=/private` finds the directory in the 0.8.10 ARM64 rootfs and fails with `read inode failed` on 0.8.9.
- The `smoke` e2e passed on VZ with the 0.8.10 bundle and the daemon built from this change. That run includes the `host_gateway` phase from #754.
- An isolated VZ daemon on 0.8.10 ran `alpine` with `-v /tmp/<dir>:/a` and `-v $TMPDIR<dir>:/b`. Both mounts were `private` on VirtioFS, read the host's files, and wrote files the host read back. `--add-host host.docker.internal:host-gateway` resolved to `10.0.2.1`.
- `cargo fmt --check`, workspace Clippy excluding the guest, `cargo xtask check-layers`, and workspace tests excluding the guest passed.

HV and x86_64 boots were not run.
