# IPv6 TCP bridge endpoints and polled downloads

Store SYN lookup keys and established-flow endpoints as `IpAddr`. The key retains the standard randomized hasher and a compact IPv4 tuple input; non-IPv4 keys include the address-family tags. Keep IPv6 flows on the polled path because inline connection owners carry IPv4 addresses. IPv6 download and retransmission segments subtract the extra 20-byte IP header from the link budget, honor the peer MSS, and use complete checksums. IPv4 GSO retains its existing eligibility and partial-checksum behavior.

The dedicated xuan-work-mbp test Mac passed 145 splicetcp library tests with all features and no ignored tests, strict all-target/all-feature Clippy, workspace formatting, and default-feature consumer compilation. Validation used Rust 1.96.0 and a fresh build directory. The new socket-backed test covers link MTU, peer MSS, large-frame mode with an IPv6 peer, a zero MSS clamped to one byte, sequence wraparound, addresses, ports, checksums, and complete payload delivery. The configured inline sink must not receive the IPv6 stream.

The user's Surge analysis (`surge-rea-analysis.md`, utun read path) distinguishes address-family classification from transport dispatch. This batch preserves that boundary: storage and polled output support IPv6, while handshake/input parsing and classifier activation remain pending. The [paired benchmark](../benchmarks/network.md#2026-10-22--tcp-bridge-address-families) measures IPv4-path costs. Original App, NE, VPN, DNS, and interface state remained unchanged. Native lifecycle and end-to-end protocol acceptance remain pending.
